## Как работает

### 1. Создание пользователя
```
User Input → Frontend → API → Database + Hysteria Config → Service Restart
```

### 2. Формат данных

**В базе данных:**
```sql
bandwidth_up: "100 mbps"
bandwidth_down: "100 mbps"
```

**В Hysteria2 config:**
```yaml
auth:
  type: userpass
  userpass:
    username:
      password: "pass"
      bandwidth:
        up: 100 mbps
        down: 100 mbps
```

### 3. Применение лимитов
- Hysteria2 применяет лимиты на уровне протокола
- Невозможно обойти через клиент
- Работает в реальном времени

## Производительность

- Минимальное влияние на производительность панели
- Ограничения применяются на уровне Hysteria2 (нативно)
- Нет дополнительных процессов мониторинга
- Перезапуск сервиса занимает ~1-2 секунды

## Безопасность

- Лимиты применяются на сервере
- Невозможно обойти через модификацию клиента
- Валидация данных на backend
- CSRF защита для всех API endpoints

## Известные ограничения

1. **Перезапуск сервиса**: При изменении bandwidth требуется перезапуск Hysteria2
2. **Активные соединения**: Будут переподключены с новыми лимитами
3. **Глобальный лимит**: Индивидуальные лимиты не могут превышать глобальный bandwidth
4. **Формат**: Поддерживаются только Mbps и Gbps (не Kbps)

## Поддержка

При возникновении проблем:
1. Проверьте логи Hysteria2: `journalctl -u hysteria-server.service`
2. Проверьте конфигурацию: `cat /etc/hysteria/config.yaml`
3. Убедитесь что `ignoreClientBandwidth: false`
4. Проверьте статус сервиса: `systemctl status hysteria-server.service`
