# Руководство: Ограничение скорости для пользователей

## Обзор

Теперь панель Isterika поддерживает индивидуальные ограничения скорости для каждого пользователя. Вы можете установить разные лимиты upload/download для разных пользователей или оставить неограниченную скорость.

## Как использовать

### Создание пользователя с ограничением скорости

1. Нажмите кнопку **"Add User"** на Dashboard
2. Заполните имя пользователя и дату истечения
3. В секции **"Bandwidth Limits"**:
   - По умолчанию установлено "Unlimited" (неограниченная скорость)
   - Нажмите **"Set Limits"** чтобы установить ограничения
   - Введите значение для Upload Speed (например: 100)
   - Выберите единицу измерения (Mbps или Gbps)
   - Введите значение для Download Speed (например: 100)
   - Выберите единицу измерения (Mbps или Gbps)
4. Нажмите **"Add User"**

### Редактирование ограничений скорости

1. Найдите пользователя в таблице
2. Нажмите кнопку **"Edit"**
3. Измените дату истечения (если нужно)
4. В секции **"Bandwidth Limits"**:
   - Переключите между "Unlimited" и "Set Limits"
   - Измените значения скорости
5. Нажмите **"Save Changes"**

### Просмотр текущих ограничений

В таблице пользователей добавлена колонка **"Bandwidth"**:
- 🔼 Зеленая стрелка вверх = Upload скорость
- 🔽 Синяя стрелка вниз = Download скорость
- "Unlimited" = без ограничений

## Примеры тарифных планов

### Basic (Базовый)
- Upload: 50 Mbps
- Download: 50 Mbps
- Подходит для: просмотр веб-страниц, социальные сети

### Standard (Стандартный)
- Upload: 100 Mbps
- Download: 100 Mbps
- Подходит для: HD видео, онлайн игры

### Premium (Премиум)
- Upload: 500 Mbps
- Download: 500 Mbps
- Подходит для: 4K видео, большие загрузки

### Ultimate (Максимальный)
- Upload: 1 Gbps
- Download: 1 Gbps
- Подходит для: профессиональное использование

### Unlimited (Безлимит)
- Без ограничений
- Использует максимальную скорость сервера

## Технические детали

### Формат в базе данных
```
bandwidth_up: "100 mbps"
bandwidth_down: "100 mbps"
```

### Формат в конфигурации Hysteria2
```yaml
auth:
  type: userpass
  userpass:
    username:
      password: "generated_password"
      bandwidth:
        up: 100 mbps
        down: 100 mbps
```

### Важные параметры

**ignoreClientBandwidth: false**
- Этот параметр ДОЛЖЕН быть `false` в конфигурации Hysteria2
- Панель автоматически устанавливает его при инициализации
- Если установлен в `true`, индивидуальные лимиты игнорируются

**Глобальный bandwidth**
- Устанавливает максимум для всего сервера
- Индивидуальные лимиты не могут превышать глобальный
- По умолчанию: 1 Gbps up/down

## Применение изменений

При создании или изменении пользователя:
1. Данные сохраняются в базу данных
2. Конфигурация Hysteria2 обновляется
3. Сервис Hysteria2 автоматически перезапускается
4. Изменения вступают в силу немедленно

**Примечание:** Активные соединения будут переподключены с новыми лимитами.

## Миграция существующих пользователей

Все существующие пользователи (созданные до обновления):
- Автоматически получают статус "Unlimited"
- Можно в любой момент установить ограничения через "Edit"
- Не требуется пересоздание пользователей

## API Endpoints

### Создание пользователя с bandwidth
```bash
POST /api/clients
{
  "username": "user1",
  "expires_at": "2026-12-31",
  "bandwidth_up": "100 mbps",
  "bandwidth_down": "100 mbps"
}
```

### Обновление bandwidth
```bash
PUT /api/clients/user1/bandwidth
{
  "bandwidth_up": "200 mbps",
  "bandwidth_down": "200 mbps"
}
```

### Удаление ограничений (установить unlimited)
```bash
PUT /api/clients/user1/bandwidth
{
  "bandwidth_up": null,
  "bandwidth_down": null
}
```

## Мониторинг

Для мониторинга использования bandwidth:
1. Проверьте логи Hysteria2: `journalctl -u hysteria-server.service -f`
2. Используйте встроенный speedtest в панели
3. Мониторьте сетевой трафик через Dashboard

## Устранение проблем

### Ограничения не работают
1. Проверьте конфигурацию: `cat /etc/hysteria/config.yaml`
2. Убедитесь что `ignoreClientBandwidth: false`
3. Перезапустите сервис: `systemctl restart hysteria-server.service`

### Пользователь не может подключиться после изменения
1. Проверьте статус сервиса: `systemctl status hysteria-server.service`
2. Проверьте логи на ошибки
3. Убедитесь что формат bandwidth корректный (число + пробел + единица)

### Скорость выше установленного лимита
1. Проверьте глобальный bandwidth в конфигурации
2. Убедитесь что `ignoreClientBandwidth: false`
3. Проверьте что пользователь использует правильные учетные данные

## Рекомендации

1. **Планирование ресурсов**: Сумма всех лимитов не должна превышать пропускную способность сервера
2. **Тестирование**: Используйте speedtest для проверки реальной скорости
3. **Мониторинг**: Регулярно проверяйте использование bandwidth
4. **Резерв**: Оставляйте 20-30% пропускной способности в резерве
5. **Документация**: Информируйте пользователей об их лимитах

## Безопасность

- Ограничения применяются на уровне Hysteria2
- Невозможно обойти через клиент
- Каждое соединение проверяется сервером
- Лимиты применяются в реальном времени
